Keep herdr-say: native messaging earns no second transport

Should lanes carry their traffic over Claude Code's own cross-session messaging, ListAgents, SendMessage, and notify_when_idle, beside or instead of herdr-say?

No. A native message is taken in at the same point as a typed one, it has no send command and here reaches only Claude sessions on this box, it is lost without a word when its receiver exits first, and no octo-lite role can send it today. Keep herdr-say as the one lane transport and change no wrapper; the four questions at the end are yours to pick.

Recommendation and findings

Each claim is tagged. documented: Claude Code's shipped tool and settings text, or octo-lite's spec and skill. observed: a spike or the live box. inferred: reasoning, or shipped code read but not run.

Recommendation

Keep herdr-say as octo-lite's one lane transport, for every runtime and node. Add SendMessage and ListAgents to no role contract, and teach no second transport in herdr-comms. At most, write the decision down as one spec sentence, so nobody rebuilds it (question 2). The one-mechanism rule asks a second transport for a stated reason, and the evidence below gives it none.

  1. Same drain point. observed In spike 3b a native message, and in spike 3c a herdr-say message, reached a session 10 s into a 30 s foreground tool call. Both were enqueued, then taken in at the next tool round as a queued_command, in the same turn. The premise in gh#213, that native reaches a busy agent mid-turn while typed text waits for idle, does not hold: herdr-say never waits for idle to type. What differs is the receipt: SendMessage returns at enqueue, herdr-say once the message's own reply is written, 25 s later in spike 3c.
  2. No role can send natively today. observed Every agents/*.md has a tools: allowlist without SendMessage or ListAgents, and an implementer session has neither. observed Yet every live session record carries a messagingSocketPath, role sessions included: 11 of 11 at this writing. Every lane agent is receive-only, so adopting native starts by widening the contracts.
  3. No send command. observed Claude Code 2.1.311 has no command that sends; claude agents --json only lists sessions. inferred So a sender that runs in a shell, herdr-say, the wake herdr-await sends, herdr-wake for Spec Chat, or any Codex or pi caller, has two native routes, neither run here. One is to speak Claude's private socket protocol, an unpublished internal that octo-lite would then track across Claude releases. The other is to start a headless claude -p turn with SendMessage allowed: a model turn per send, whose process exits with its from= socket, so it cannot hear a reply and a later hold or expiry notice reaches no one. Either route reaches only a live Claude session, on this box only a local one: never a Codex or pi target, another node (question 6), or a parked agent, which nothing native resumes.
  4. Lost without a word. observed In spike 6b a native message queued at a session inside a long tool call, which then closed, was never taken in, and its sender, told it was "in that session's inbox, not yet read by its Claude", heard nothing in 45 s. documented herdr-say exits 1 in the same case and names the message as never taken in (#transport-say-rate-limit). observed To a closed session SendMessage fails at once, "No agent named 'spike-ann-1383-b' is reachable." documented Only to a parked one does herdr-say do better: it resumes the agent from its parked line (question 2).
  5. Box-wide, not session-scoped. documented ListAgents lists "other local Claude sessions on this machine", 12 in spike 1, whatever Herdr session runs them. inferred Native addressing crosses octo-lite's isolation unit, the Herdr session (#session); this box runs only the default session, so this was not observed.
  6. Mode holds do not bite here today. observed Every live session's transcript shows permissionMode auto, a code reviewer's included, though code-reviewer is the one contract that does not set it. inferred Shipped code puts only bypassPermissions, or plan with bypass available, in the bypass class, so auto, default, and plan sessions share the prompting class and mode parity never holds a lane's message. observed A forced hold held the message, told the sender, left Herdr reporting the receiver idle, and expired when the receiver closed.
  7. notify_when_idle is a turn end, not a task end. observed It fired while its target still ran its background shell (spike 3), fired at once on a target already idle (spike 5), and reported "exited at 06:35 before going idle" when the tab closed mid-turn (spike 5b). It has no --since, no Codex or pi caller, and no Codex or pi target; herdr-await covers all three.
  8. Native carries provenance that typed text lacks. observed The receiver records a native message with origin kind peer, the sender's verified pid and process start, msg_id, and name; a herdr-say message is recorded with origin kind human, as if the operator typed it. inferred This is the one thing native does better, and it cuts both ways: Claude frames a peer message as never the user's approval, so a human gate answer the operator relayed natively might not be acted on.

The seven questions, answered

The questions as gh#213 and the brief put them, each answered first, then its evidence.

1. Identity

Answer. The record Claude already keeps maps a pane to its native address and back, and --name could make the names equal; nothing needs either while herdr-say stays.

  • observed A native name derives from the cwd: ann1383-fc for the lane owner Herdr names ann1383-native-messaging, and ann1383-impl-03 for this worker, implementer-ann-1383 in Herdr. The lane record's owner is neither: it is the pane w7P:p2 (#lane-record).
  • observed claude --name spike-ann-1383-b set the native name exactly, its record's nameSource user. Resumed under the same --name, the session answered to it again with a new pid and socket, and the sender was told it was "messaging a new session for the first time under a previously used name".
  • observed Owner pane to native address: herdr-claude-session PANE already returns Claude's session record, whose name and messagingSocketPath are the address.
  • observed from= back to a pane: the socket is /run/user/1000/cc-socks/<pid>.sock, and the receiver's transcript records verifiedPeerPid and verifiedPeerProcStart. HERDR_PANE_ID in /proc/<pid>/environ names the pane: pid 780810 gave w7P:p4.
  • documented Claude calls the from address "Sender-asserted on the socket lane: a label, not an identity proof"; the pid is the verified part.
  • observed The socket directory is no liveness source: it held 43 sockets for 13 live session records.

2. Delivery semantics

Answer. One queue and one drain point; native is weaker on confirmation, on a receiver that exits before taking the message in, on parked targets, and on rate limits, equal on a closed target that was not parked, and better only on a blocked target.

  • observed Idle target: a native message started a turn at once, and the reply went back to its from address (spike 2); a typed one starts a turn the same way.
  • observed Busy target: both are taken in at the next tool round (finding 1).
  • observed Blocked target, an open AskUserQuestion dialog: herdr-say exited 75 at once. SendMessage queued the message, the pane showed its one-line preview above the dialog, and Claude took it in with the dialog's answer (spike 4).
  • observed Closed target, not parked: both fail at once and tell the sender. SendMessage answered "No agent named 'spike-ann-1383-b' is reachable." (spike 5c); herdr-say to a name no agent and no parked line carries exited 1 with Herdr's agent_not_found (a review probe).
  • documented Parked target: herdr-say resumes it from the latest parked line, then delivers (#transport-wake-parked). Only herdr-close --park writes that line; a plain herdr-close writes a closed line, which resumes nothing. inferred SendMessage fails at once here too, since parking closes the session's tab as closing does.
  • observed Receiver exits before taking it in: lost, and the sender is not told (finding 4).
  • observed At 04:51 both scratch sessions' turns died at once on "All credentials for model claude-opus-5-5 are cooling down". inferred A native message drained into such a turn is spent and never sent again, where herdr-say sends again until the agent processes it or exits 69 (#transport-say-rate-limit).
  • inferred Native has no exit-code contract: a sender learns of a hold or its expiry later, as a notice inside its own conversation, and of a loss not at all.

3. Waiting

Answer. No: notify_when_idle can neither replace herdr-await nor simplify it.

  • documented It is one-shot, from the main conversation only, for Claude sessions on this machine only: one notice when the target "next goes idle (or exits)", else an expiry notice. When the subscriber itself holds peer traffic, the notice goes to its user, not its Claude.
  • inferred The expiry is 12 h in shipped code, 43,200,000 ms.
  • observed It ends at a turn end, not a task end, fires at once on a target already idle, and reports an exit (finding 7).
  • documented herdr-await already covers what it lacks: --since for an agent still at its task, gone for a tab closed by anyone, a wake by message that reaches a Claude, Codex, or pi caller, and an end without a wake when its caller is closed or parked (#transport-await).

4. Permission-mode holds

Answer. Held or expired messages are acceptable today only because no lane holds; native for lanes would need a rule that every lane share one permission class, and herdr-say needs none.

  • documented crossSessionInbound is accept, hold, or refuse. Unset means mode parity: a message "auto-delivers only when the sending session's permission-mode class matches yours (bypass↔bypass or prompting↔prompting)".
  • observed On this box every live session runs auto, and every contract sets auto except code-reviewer, which sets none. observed A code-reviewer session runs auto too: every permissionMode record in a code reviewer's transcript is auto, so every lane is auto.
  • inferred Only bypassPermissions, or plan with bypass available, is the bypass class in shipped code, so every lane is prompting and no lane holds another's message.
  • observed With crossSessionInbound: "hold" on the receiver: the sender got "[Cross-session delivery notice] Your message to another session was held by that session"; the receiver's pane showed "Held peer message", "not delivered to Claude (1 held)"; Herdr still reported it idle; closing the receiver sent "not approved before expiry" (spike 6).
  • inferred Held messages live in the receiver's memory, at most 100, and expire at its shutdown, so parking a holding session discards them.
  • observed A bypass scratch session was not spiked: the auto-mode classifier refused to spawn it, and that was not worked around.

5. Audit

Answer. Hand-off logs need nothing either way, since they record hand-off moments, not messages; what native would cost is the confirmation and the operator's view.

  • documented A hand-off line is written at a moment, an attempt, review, gate, park, or close (#handoff-fields), and only a herdr-say exit 0 confirms a worker's report (#roles-goal).
  • observed In the receiver's pane a typed message shows in full as a prompt line; a native one as "Message from @spike-ann-1383-a:" with a one-line preview to expand.
  • observed In the receiver's transcript a native message is origin peer with its sender's verified pid; a typed one is origin human (finding 8).
  • inferred Native lane traffic would need its sender to record each send it relies on, because native success means only "in the inbox": the confirmation herdr-say's exit 0 already is.

6. Mixed runtimes and remote nodes

Answer. herdr-say must stay for Codex, pi, shells, and other nodes, and one wrapper cannot usefully choose native per target, since a wrapper can send natively only through Claude's private socket protocol or a headless model turn that cannot hear a reply (finding 3).

  • documented notify_when_idle "is only supported for Claude sessions on this machine", and a message to another machine goes "via Anthropic's servers" over Remote Control.
  • observed This box reaches the model through an API key helper and a proxy base URL. inferred Remote Control needs a claude.ai login, so no native path reaches another node here; the herdr-node routing inside herdr-say that gh#202 proposes stays the node path.
  • inferred A per-target choice could live in a wrapper, on one of the two routes in finding 3, or in each role's prompt, as two recipes with two failure models.

7. Contracts

Answer. No: neither agents/*.md nor herdr-comms should name the native channel as transport, and the allowlists already keep it out.

  • observed The tools: allowlists date from f50b847, 2026-07-22.
  • inferred The exchange gh#213 reports ran on sessions outside those allowlists; the main box was not read.
  • inferred A lane can still receive a native message from a plain Claude session, and having no SendMessage, answers it in its own pane unless it replies by herdr-say to the pane its sender's pid carries; question 3 asks whether that needs one line.

05

Options, ranked

Judged by the elegant-lean frame and the one-mechanism rule (peer-seams.spec.html#rule-one-mechanism, annotateanything).

1 · pick

Keep herdr-say only

Cost. None, or one spec sentence.

Keeps. One transport, one exit-code contract, one failure model, every runtime and node, session scope.

Loses. Peer provenance in the receiver's transcript, and queueing at a blocked target.

2

Native as a Claude-to-Claude fast path

Cost. SendMessage and ListAgents in the orchestrator and meta-operator allowlists; herdr-spawn passing --name; a herdr-comms section on choosing and on what success means; spec sentences on holds, loss at exit, no resume, and box-wide scope; two failure models for good.

Gains. No retry at a blocked target, peer provenance.

Verdict. No reason for a second mechanism: the drain point is the same.

3

Replace herdr-say

Not possible. No native path reaches a Codex or pi target, another node from this box, or a parked agent, and every shell sender (any Codex or pi caller, herdr-wake, herdr-await's wake) has only the two costly routes in finding 3.

Your questions

Four, each with options and my pick.

Question 1

Which transport carries lane traffic?

a. herdr-say only. b. Native as a Claude-to-Claude fast path beside it. c. Native instead of it.

Pick: a. Same drain point, weaker confirmation, and no reach beyond Claude on this box.

Question 2

Write the decision down?

a. One sentence in the spec's Not present list, which exists so nobody rebuilds what was ruled out. b. Nothing: this report and the allowlists suffice.

Pick: a. One sentence, and the next lane that meets SendMessage finds the answer in the spec.

Question 3

Do you message lanes from your own plain Claude sessions?

a. No: nothing to add. b. Yes: one herdr-comms line, answer a cross-session message by herdr-say to the pane its sender's pid carries in HERDR_PANE_ID.

Pick: a, until it happens; b is one line when it does.

Question 4

Make native names equal Herdr names?

a. No. b. Yes: herdr-spawn passes --name, so ListAgents rows read as lane and worker names.

Pick: a. With option 1 nothing reads those names; b becomes part of option 2 if you pick it.
