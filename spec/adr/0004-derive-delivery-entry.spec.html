ADR 0004: delete the readiness envelope, derive delivery entry from (issue, pr, head)

Specifications / delivery lifecycle / ADR 0004

Decisions closing the operator grill on octo-lite issue 34, 2026-07-27.

Status

Accepted.

Context

Delivery entry required a hand-assembled readiness envelope of roughly thirty fields, and the operator judged that ceremony insane.

The TUR-425 green pass proved every envelope field is mechanically derivable, because the orchestrator assembled the whole envelope by hand from canonical sources and it passed, which shows the hand assembly added ceremony, not trust.

ADR 0003 already had the loop derive its worktree from the process working directory and its branch from git and drop the loop trust root, so a residual readiness envelope was a half-finished derivation left partly hand-declared on top of an already-lean loop.

Issue 33 proposed a host re-pin operation, which is machinery to support reusing one orchestrator across issues, an arrangement the operator ruled out.

Decision

Entry declares three facts

A delivery pass declares exactly the issue, the PR, and the head, and the readiness envelope is deleted as an input concept, not simplified.

The loop derives every other binding at fire from its one canonical source, Linear, the forge, git, the pinned shaping-verdict comment, and any QA artifacts, so deriving each binding is the verification.

The loop fails loud on any inconsistency, in particular when the declared head, the PR head, and the worktree head disagree within one fire, stopping before any mutation rather than accepting an asserted field.

The shaping-verdict head is not a fourth head that must equal the declared head but immutable readiness evidence the declared head must descend from, so the entry gate admits any declared head that adds commits on top of the shaping-cleared head and refuses one off a different or unshaped base.

This ancestor-descent rule supersedes the original strict four-head equality, which made implement a one-time entry at the exact shaping head and blocked seam-by-seam re-entry within a single slice once the first green advanced the head.

The loop journals the full derivation as an output receipt produced by the fire, replacing the hand-assembled input envelope, so the durable record is what the loop verified rather than what a caller asserted.

One orchestrator per issue, enforced

Exactly one orchestrator owns an issue together with its lane, worktree, and pins, born together at the correct head and retired together when the work is done.

A fire whose declared issue does not match the worktree lane, branch, and PR is refused with a clear error that names the one-orchestrator-per-issue rule and the fix of spawning a lane for that issue, so the rule is enforced rather than merely gated.

Phase transitions re-spawn fresh at current truth rather than re-pinning an existing session, provision pins are born correct and die with the session, and no re-pin support path exists, so issue 33 is superseded.

Anti-forgery unchanged

The anti-forgery property is unchanged or stronger: the loop keeps deriving its identity from the process working directory and git and never reads the host-authored provision record to enter, the record stays cleanup-ownership only per ADR 0003, the OpenAI reviewer relay-provenance gate is retained, and the head cross-check is a stronger guarantee than a hand-declared field it replaces.

Consequences

Delivery entry becomes one command carrying three facts, and the readiness envelope, its builder, and its readiness check are removed from an already-lean loop.

The loop does more work at fire deriving and cross-checking, and a single head inconsistency now stops the pass loudly instead of being silently reconciled by a hand-declared field.

Reusing one orchestrator across issues is no longer possible, and the re-pin operation is removed rather than maintained.

A slice may now deliver seam by seam, each green re-entering the loop at a head that descends from the shaping-cleared head with the host pushing each green so the PR head tracks, and this deliberate trust-model relaxation is guarded by a real shaping review rather than shipped as a hotfix.
