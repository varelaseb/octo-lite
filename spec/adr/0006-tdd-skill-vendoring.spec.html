ADR 0006: pinned upstream TDD skill

Specifications / octo-lite / ADR 0006

Supersedes ADR 0002. Decision behind the tdd pin and spec-named test seams.

User stories

As an operator, I can update the pinned upstream tdd skill through skillfile and keep its single seam-gate patch applied.

As an implementer, I confirm test seams against the canonical spec rather than the user, and a spec without deep-module seams returns to shaping.

Context

octo-lite carried a tdd skill of its own, while mattpocock/skills carries a craft tdd skill with test-quality guidance octo-lite's lacked.

octo-lite's own skill restated rules its specs own, so each could drift from the other.

The upstream skill confirms test seams with the user, but octo-lite runs no human loop mid-implementation: its seams come from the accepted spec.

A hand-copied third-party skill drifts silently, and local edits to it die on the next upstream update.

Decision

octo-lite's tdd skill is mattpocock/skills skills/engineering/tdd, pinned at an exact upstream commit and unchanged but for one patch.

The one patch takes test seams from the canonical spec, never the user, as test seams states.

The upstream rule that refactoring is not part of the red-green loop stays verbatim; cleanup reaches a PR as review notes marked to fix.

skillfile manages the pin: its manifest and lockfile hold the upstream commit, and it carries the patch across upstream updates (install).

Why

Implementers gain upstream's test craft, seams, anti-patterns, and vertical slicing, which octo-lite's own skill lacked.

One patch is the smallest difference that fits delivery with no human loop, so an upstream update stays a pin bump.

skillfile pins exact revisions and preserves patches across updates, so the third-party skill neither drifts nor loses its patch.

Alternatives rejected

OptionRejected because
Keep octo-lite's own tdd skillIt lacks upstream's test craft and restates rules the specs own
Copy the upstream skill by handIt drifts silently, and local edits die on each upstream update
The npx skills installerFor this use it is a strict subset of skillfile, with no lockfile and no patch preservation, and adopting both would split ownership of the same files
A second patch keeping octo-lite's honest-red rule, that a test failing for setup, syntax, or dependency reasons is not redDropped by operator ruling, so the skill keeps one patch

Consequences

Implementers gain upstream test craft at the cost of octo-lite-specific prose, which the specs carry.

A red that fails for an unintended reason is no longer textually forbidden: an accepted weakening, revisited only on observed regression.

An upstream update is a skillfile update with the patch re-applied, never a manual re-copy.

Standalone cleanup waits for a review note, so refactor latency is bounded by review cadence rather than implementer discretion.
