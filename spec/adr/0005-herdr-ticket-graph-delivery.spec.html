ADR 0005: Herdr ticket-graph delivery

Specifications / delivery lifecycle / ADR 0005

Decision from GitHub issue 95, 2026-09-01.

Status

Accepted.

Context

The post-shaping loop accumulated role resolution, receipts, journals, exact-model gates, verdict publication, QA gates, and lifecycle transitions around ordinary implementation.

A reviewed spec already has implementation tickets whose blocking relations expose the work that can safely run in parallel.

Decision

spec-chat-shape finishes with a reviewed spec, its issue, and dependency-linked implementation tickets.

implement-spec is explicit-only and owns post-shaping delivery.

It launches temporary Herdr explorer, implementer, merger, and reviewer agents directly, outside roles.toml, role contracts, and the legacy Workflow loop.

Implementers fill the ready ticket frontier in isolated worktrees and branches while one merger at a time integrates completed commits onto one PR branch.

Linear records the actual ticket graph and live work state, with Done reserved for integrated and pushed work.

After full integration, /code-review runs once, one implementation agent fixes all findings, and review reruns once before the PR becomes ready for human review.

octo-lite-loop remains only as a compatibility redirect to implement-spec.

Consequences

Independent tickets run concurrently and task dependencies, not a fixed phase sequence, control throughput.

Agents communicate through durable pointers and commits instead of copied briefs and machine receipts.

The workflow gives up deterministic role and verdict gates in exchange for simpler execution, direct observability, and Linear state that reflects actual work.

This decision supersedes ADR 0002 through ADR 0004 only where they prescribe post-shaping implementation-loop ceremony; their skill-vendoring, historical, and non-delivery decisions remain.
