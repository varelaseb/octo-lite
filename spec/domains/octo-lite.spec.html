Specifications / octo-lite

This spec describes only what exists in this repository today.

It replaces the operating-model, delivery-lifecycle, role-runtime, and operator-control domain specs, which described deleted apparatus; they remain in git history.

User stories

As an operator, I can shape an idea into a reviewed spec and ticket graph, then have it delivered on one PR ready for my review.

As an operator, I can install or verify octo-lite with one script and a plain git pull keeps it current.

Install

scripts/install-octo-lite symlinks skills/*, agents/*.md, profile/AGENTS.md, and executable helpers into the Claude and Codex profiles and ~/.local/bin; --check verifies the links.

A path already linked by a peer repository is left to that peer, and dangling links are pruned.

Spec Chat skills link straight from a sibling spec-chat clone; only the third-party tdd skill is pinned, by Skillfile into agents/skills (ADR 0002).

Roles

agents/*.md are the hand-written role contracts: orchestrator, implementer, code-reviewer, and meta-operator; none pins a model.

Every spawned worker with a role contract (implementer, code-reviewer, shaping-reviewer) loads it: Claude through --agent ROLE, Codex as developer instructions via herdr-spawn --role ROLE.

Delivery

spec-chat-shape produces the reviewed canonical spec, its Linear issue, and dependency-linked implementation tickets; a processed human Finish review accepts the spec.

implement-spec runs one shaping-review worker, then fills the ready ticket frontier with implementer workers, each in its own worktree.

One merger at a time integrates finished commits onto the single integration branch and PR.

A code-reviewer judges the integration head, and findings get bounded repair until review is clear and required checks pass.

Linear stays truthful: a ticket is Done only once integrated and pushed, and a merged accepted PR completes the worklane.

Transport

herdr-spawn opens one tab and agent at an explicit worktree, and herdr-say delivers a message, returning only once Herdr observes a state change.

There is no acknowledgement step, inbox, or drain.

Lane record

The workbench lane record format owns the shared TOML keys. Octo-lite adds only its delivery state and writes those keys at the moments below.

Human gates

Spec review, acceptance of delivered work, merge of unaccepted work, preproduction promotion, and live traffic shifts require explicit human instruction.

Not present

There is no sweep or host timer, loop workflow, role resolver or roles.toml, control CLI, owner file, readiness envelope, trust root, or conformance checker; do not rebuild them. The removed owner file was coordination and control state; the lane record is a read-only declaration for observation that nothing gates on.
