Disk

Specifications / Disk

This spec states how octo-lite keeps the disk its lanes use: each agent's scratch folder, what parking an agent and closing a lane remove, and the warning the operator gets before the box's disk fills.

Spawning, closing, and parking agents are in the Herdr transport spec; the hook that checks the disk is in the Command time spec; lane teardown and lane notes are in the octo-lite spec.

User stories

As an operator, every temporary file an agent's commands make lands in that agent's own scratch folder, which goes when the agent is closed or parked, so nothing an agent made is left in /tmp with no owner.

As an operator, parking an agent frees the installed packages in its own worktree, which it installs again when it next needs them, while my box's main checkouts, its install clones, and any tree another agent works in keep theirs.

As an operator, a finished lane leaves no disk behind but its archived record, hand-off log, and notes, and its notes hold only what cannot be made again.

As an operator, I am told when my box's disk reaches 85% full and again at 90%, with the folders holding the most of it, so I hear before a full disk crashes a service, and the warning only tells me: it never removes, blocks, or stops anything.

Acceptance criteria

Given a lane owner, When it spawns a worker, then the worker runs a test suite that makes temporary folders, Then each of those folders is inside the worker's own scratch folder, which no other agent shares: no screen shows it.

Given a lane owner whose worker has made temporary files, When the owner closes the worker, Then the worker's scratch folder is gone, and the owner's own scratch folder is still there: no screen shows it.

Given a lane owner whose idle worker has made temporary files, When the owner parks the worker, Then the worker's scratch folder is gone: no screen shows it.

Given a lane owner that parked its worker after the worker made temporary files, When the owner sends the worker a message, then the resumed worker makes a temporary file, Then that file is in a scratch folder of the worker's own that holds nothing from before its park: no screen shows it.

Given the operators of two Herdr sessions, each with a lane agent under the same name that has made temporary files, When the operator of one session closes its agent, Then the other session's agent keeps its scratch folder: no screen shows it.

Given an operator who updates octo-lite while a lane agent started before the update still runs, When the agent's owner closes it, Then the close ends the agent and its processes as before and removes no file: no screen shows it.

Given a lane owner whose idle worker's worktree has its packages installed, When the owner parks the worker, Then the node_modules folders Git ignores in that worktree are gone, and every other file in it is unchanged: no screen shows it.

Given an operator whose idle agent works in the box's main checkout of a repository, on its main branch, When the operator parks that agent, Then the main checkout keeps its node_modules folders: no screen shows it.

Given an operator whose idle agent works in a live install clone, such as octo-lite's own, When the operator parks that agent, Then the install clone keeps its node_modules folders: no screen shows it.

Given a lane owner whose idle worker's worktree is also the working folder of another live agent, When the owner parks the worker, Then the worktree keeps its node_modules folders: no screen shows it.

Given a lane owner parked at a human gate, whose park removed its worktree's node_modules folders, When a review hand-off resumes it, then it restarts its prototype, Then it installs the packages again with its repository's install command before the restart, and the prototype runs: no screen shows it.

Given an operator with a finished lane whose owner and worker have each made temporary files, and another lane running, When the operator closes the finished lane's space, Then no scratch folder of the finished lane's agents is left, and the other lane's agents keep theirs: no screen shows it.

Given an operator with a finished lane whose PR merged and whose worktree holds no uncommitted work, When the operator tears down the lane, Then the lane's worktree is gone, and its repository's main checkout is unchanged: no screen shows it.

Given an operator with a finished lane whose worktree holds uncommitted work, When the operator tears down the lane, Then the worktree is kept with that work, and the operator's report of the lane's close names it: no screen shows it.

Given a lane worker that draws frames from a recording to read it and writes a report of what it read, When the lane closes, Then the lane's archived notes hold the worker's report and none of those frames: no screen shows it.

Given an operator on a box whose disk is just under 85% full, a fixture that must be added to provide it, When a lane agent runs a command that fills it past 85%, Then the operator gets one message saying how full the disk is and how much is free, and naming the folders holding the most of it, each with its size: no screen shows it.

Given an operator told that its box's disk is past 85% full, When lane agents run more commands while the disk stays under 90% full, Then that one message is the only disk message the operator has: no screen shows it.

Given an operator told that its box's disk is past 85% full, When a lane agent runs a command that fills it past 90%, Then the operator gets one more message saying how full the disk is and how much is free, and naming the folders holding the most of it, each with its size: no screen shows it.

Given an operator told that its box's disk is past 90% full, When the disk is freed to under 80% full, then a lane agent runs a command that fills it past 85% again, Then the operator gets a new message saying how full the disk is: no screen shows it.

Given an agent in a Herdr session with no operator, on a box whose disk is just under 85% full, a fixture that must be added to provide it, When the agent runs a command that fills it past 85%, Then the agent is told, beside that command's result, how full the disk is and how much is free: no screen shows it.

Given a lane agent on a box whose disk is past 90% full, a fixture that must be added to provide it, When the agent runs a command, Then the command runs and its result reaches the agent as it would without the warning, and the warning removes nothing: no screen shows it.

Modular boundaries

herdr-spawn owns giving each agent its scratch folder, and herdr-close owns removing it at a close or park and removing a parked agent's packages. The caller-facing seam is the TMPDIR each agent's tab carries, which every program the agent runs reads for where its temporary files go. Direction is self-contained: the wrappers extend their own spawn, close, and park, and agents' programs depend on TMPDIR as they do on any box; no role or skill names the folder's path. Observable scope: the folders under /tmp and in a parked agent's worktree.

octo-lite's command-time hook owns checking the disk after each shell command and sending the warning. The caller-facing seam is the message the operator's pane receives, or, with no operator, the line beside the agent's command. Direction is external-provider: the hook depends on herdr-say and the session's operator.toml; nothing depends on the warning. Observable scope: the operator's messages and the agent's command line.

Scratch

herdr-spawn gives each agent it starts a scratch folder of its own, under the box's /tmp and named after its Herdr session and its agent name, created empty, and exports it as TMPDIR into the agent's tab, as it exports the caller's HOME. Every program that puts its temporary files where TMPDIR says, as mktemp, Python's tempfile, and Node's os.tmpdir do, puts them there, so the test suites, browsers, and recordings an agent runs leave their temporary files in its folder.

herdr-close removes the scratch folder of each agent in the tab or space it closes, a park included, once it has stopped the processes started there. Agent names repeat across Herdr sessions, so a close removes only its own session's folders. A resumed agent gets an empty scratch folder again under its old name.

An agent writes its temporary files under $TMPDIR, never at a path of its own in /tmp, and keeps there anything it can make again, such as frames drawn from a recording to read it. What must outlive the agent goes where it is kept: a report in the lane's notes, work in its worktree and the PR. The role contracts say so where agents write.

An agent started before its box had this has no scratch folder, and its close removes nothing more than it did, so a box updates octo-lite whenever it is ready, with nothing to migrate. Nothing sweeps /tmp: a folder left there before the update stays until the box owner removes it.

Parking

Parking an agent also removes the node_modules folders Git ignores in its worktree, the folder it works in, since its repository's install command restores them and they are most of an idle lane's disk. Only installed packages go: every other file, tracked or not, stays.

Only a worktree of the agent's own lane counts: a Git linked worktree not checked out on its repository's main branch. A box's main checkouts and its live install clones stay on main and serve every lane and the box's installed tools, so they keep their packages. A worktree that a process outside the parked agent's tab still has as its working folder, such as another live agent's, keeps its packages too, since that process may be using them.

A resumed agent that finds its packages gone installs them again with its repository's install command, as the target AGENTS.md names it, before it runs anything that needs them, such as its tests or the prototype. The orchestrator and implementer contracts say so where they resume.

Closing an agent removes no packages: a closed worker's worktree goes whole once its commits are integrated, and the lane's own worktree goes at lane close.

Lane close

At teardown the owner removes its workers' worktrees (teardown), and the operator, once it has closed the lane's space or owner tab, removes the lane's own worktree, the one it added at lane start. It removes it with Git's worktree remove, which keeps a worktree holding uncommitted work, and its report of the lane's close names a worktree so kept. Closing the lane's space or owner tab removes the scratch folder of every agent it closes, so a finished lane leaves only its archived record, hand-off log, and notes.

Disk warning

After each shell command any agent runs, octo-lite's command-time hook also reads how full the box's disk is, as df shows it for the root filesystem. The read is cheap and needs no timer or service: the commands that fill the disk are what check it.

When the disk is 85% full or more, the session's operator, the pane in its operator.toml, gets one message by herdr-say, and at 90% one more. Each says how full the disk is and how much is free, names the folders holding the most of it, each with its size, and says that nothing was removed and that each lane frees only what it made. Each level is told once per session until the disk is back under 80% full; then each is told again the next time the disk passes it.

In a session with no operator, the agent whose command found the disk past a level is told instead, in that command's line.

The warning only informs, as every hook octo-lite registers does (rule): it never removes, blocks, or stops anything, and the operator decides what to free and asks the lanes holding it. A failed check or send adds nothing, and the command and its result are as they would be without it.

Not built

octo-lite keeps no per-lane disk budget and has no disk command: scratch folders and packages end with the agent that made them, and the warning names what holds the disk. It sweeps nothing: no /tmp sweep, no cache cleaning, and no other lane's files, so every removal here is of what its own agent made. It removes no build output, since only installed packages have one restore every repository names.

Install: the installer links and registers nothing new for this, since the wrappers and the hook it already installs carry it, so every install run still passes as the first (rule).
