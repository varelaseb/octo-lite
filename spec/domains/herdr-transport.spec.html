Herdr transport

Specifications / Herdr transport

This spec states how octo-lite places, messages, awaits, parks, and resumes lane agents over Herdr, one Herdr session at a time.

Lane records, hand-off logs, delivery, and human gates are in the octo-lite spec.

User stories

As an operator, I see each lane in its own Herdr space named after the lane, holding its owner and every worker of that lane, while I work in a space of my own, and Claude's own list of the sessions on my box names each of them as Herdr does; closing a finished lane's space leaves nothing of it running.

As an operator, a lane never stalls silently: every worker delivers its result to its lane owner as a message, the owner, whatever agent runs it, wakes as soon as a worker it waits on stops or its tab closes, resumes one whose turn died on an API error, recovers any other worker that ended without reporting, and tells me, an owner whose turn dies while I await its reply is resumed the same way, a worker whose owner cannot be reached sends its result to me and stops instead of retrying without end, and every report reaches me as a message.

As an operator on a box short of memory, I can park an idle lane owner or worker so it holds no memory while it waits, and a later message to it resumes it under the same name with its conversation intact.

As an operator running several Herdr sessions on one box, I work in each without coordinating: an agent in one session never sees, wakes, or tears down a lane of another.

As an operator, a message herdr-say sends, or a spec review hand-off, whose agent's turn dies at once on an API rate limit is sent again until the agent processes it, and a sender whose message never got through is told so, so no agent sits idle on a message it never read.

As an operator, the status my lanes' Claude agents send each other reads in their conversations as a teammate's message, never as my own input: a Claude agent reports to a Claude agent by Claude's own messaging, falling back to herdr-say only when that cannot reach it, and a Claude agent waiting on another learns the wait ended from a background task of its own.

Modular boundaries

The Herdr wrappers (octo-lite-start, herdr-spawn, herdr-say, herdr-await, herdr-close) own placing lane agents in spaces, messaging them, waiting on them, parking and resuming them, and closing tabs and spaces. The caller-facing seam is each wrapper's arguments, its printed pane= and workspace= lines, and how herdr-await tells its caller a wait ended: a Claude caller's background-task notice, else a message. Direction is external-provider: the wrappers depend on the Herdr CLI, the session key Herdr exports, and Claude's own per-process session file, with --resume for parking, the session's transcript for confirming a Claude agent processed a message, and its messaging address for a native report; roles and skills depend on the wrappers, never the reverse. Observable scope: Herdr spaces, tabs, and agents, the names Claude's own session list shows, the messages Claude agents' panes show, and process exit.

The herdr-comms skill's wait recipe owns when lane agents report, wait on each other, park, and resume. The caller-facing seam is that recipe, which the orchestrator and meta-operator contracts and the implement-spec skill link where they send work, wait, or close. Direction is self-contained and downward: the recipe uses the wrappers, and role contracts link it, never the reverse. Observable scope: the messages lane agents' panes show, Herdr spaces and tabs, and parked lines.

Roles

Waiting agents hold no memory: the fleet operator parks a lane owner idle at a human gate, on another lane, or held back for load, and resumes it by sending it the wake message, or when load allows, one owner at a time as memory frees. A parked owner is resumed, never relaunched fresh; only an owner with no parked line and no live pane is relaunched. A lane owner parks a worker it would otherwise keep idle through a long wait, such as a human gate or another lane, and messages it to resume; a worker whose result is consumed is closed, not parked. A resumed owner first sets its lane record's owner to its new pane, then acts on the message that resumed it. The meta-operator and orchestrator contracts and the herdr-comms and implement-spec skills state these moves where they wait or close.

Every lane owner, and every operator-like pane, runs under a /goal for its lane outcome, so goal check-ins keep invoking it while work is unfinished. Every report goes to its recipient as a message, by Claude's own messaging or herdr-say as the native report rule picks; text left in the sender's own pane is not reported. A worker's last step sends its result to the owner pane its brief names, and only a native send Claude reports delivered, or a herdr-say exit 0, confirms the send; a herdr-say send that does not exit 0 is sent again, a bounded number of times, unless it exits 69, which its sender never sends again. When no send to the owner is confirmed, the worker sends its result once to the operator's pane, read from the session's operator.toml, and stops whether or not that send is confirmed, so an unreachable owner never holds a worker in a send loop. The operator brings the lane's owner back as parking states and forwards it the result. Each time the owner sets a worker to work, by its brief, a resume, or a repair, it sends that work with herdr-await, which starts one wait on that worker by name; the wait ends when the worker is idle, done, stuck on an interactive prompt, or gone, and its end wakes the owner, whatever agent runs the owner, as the wait states, so a worker that stops wakes an owner idle on it, with no timer. A send that is not confirmed ends the wait at once, and its wake says so. An owner relaunched from a park starts one such wait, sending nothing, on each worker it still waits on, since its earlier waits ended with its process. When a wait on a worker it still waits on ends, the owner reads the worker's pane. A finished result there is consumed as the worker's report. A turn that ended on an API error is resumed by sending the same worker continue the same way, which sends again while a rate limit lasts; a resume that is not confirmed leaves the worker blocked. A worker still at its task, such as one waiting on its own background command, gets a new wait that ends only once the worker has changed state since the stop the owner read and has stopped again, so an owner never wakes again on a worker that has not moved, and a worker that works and stops before that wait starts still ends it. Otherwise the worker is blocked, and the owner recovers or respawns it. Except for a worker still at its task, the owner tells the operator which worker ended without reporting and what it did. The fleet operator does the same for a lane owner it sends work it awaits a reply to: it sends that work with herdr-await, with the same rules when the wait ends, and never a standing wait on every owner. The herdr-comms skill states these rules once, as its wait recipe, and the orchestrator and meta-operator contracts and the implement-spec skill link that recipe where they send work.

An optional operating model given to herdr-spawn reaches the agent at start and passes to every agent it spawns, and each spawn forwards the caller's HOME.

Herdr session

The Herdr session is octo-lite's isolation unit: an agent sees, messages, parks, wakes, and tears down only the lanes of its own session, and sessions need no coordination. Every wrapper and role acts in its caller's session and reads and writes only that session's state.

The session key is the Herdr session name, read from Herdr alone. Herdr exports the name as HERDR_SESSION to every pane of a named session, and a pane of the default session has none, so a process reads the key as ${HERDR_SESSION:-default}. The Herdr CLI selects its own session by the same variable, so a process outside any pane that sets it acts in that session, and one that does not acts in the default session; a set HERDR_SOCKET_PATH pins the session over it. Herdr limits session names to ASCII letters, digits, ., _, and -, so the key is safe as a path component. Any repository that scopes its own state by Herdr session reads this same key from Herdr directly.

octo-lite's state directory for a session is $XDG_STATE_HOME/octo-lite/ for the key default, and $XDG_STATE_HOME/octo-lite/sessions/<key>/ for any other key, as Herdr keeps its own named sessions under sessions/<name>. It holds the session's lanes/ directory, with each lane's record, hand-off log, and notes, and the archive, and the session's operator.toml and operator.handoffs.jsonl; the store table gives each its lifetime. octo-lite-state prints the caller's session state directory, and roles and wrappers locate lane and operator files through it. The onboarding file belongs to the box, not a session, and stays at $XDG_STATE_HOME/octo-lite/onboarding.toml.

Herdr pane, tab, and space ids are unique only within a session; another session repeats them. Every id in a session's state is read and acted on in that session: a message, park, wake, or close by id reaches only the caller's session, unless a wake owner names its own session (wake owner), and a close stops only processes of the caller's session. No record key names a session.

The one box-wide service, Spec Chat's review service, runs in one session and wakes owners of every session, so a review row's owner names its session: a lane registers with --owner "${HERDR_SESSION:-default}/$HERDR_PANE_ID", for example second/wP:p2. herdr-wake checks and wakes a <session>/<pane> owner in that session, with that session's state for its parked lines and its operator's pane, and a bare pane in its caller's session; it never searches sessions for a pane, since ids repeat across them.

Transport

herdr-spawn opens one tab and agent at an explicit worktree, and herdr-say delivers a message, returning only once Herdr observes a state change and, for a Claude agent, once the agent has processed it. A target blocked on interactive input gets nothing typed, and herdr-say exits 75, not delivered, so the caller retries once it frees.

A Claude agent whose turn dies at once on an API rate limit, as it does while Claude's credentials are cooling down, has not processed the message, though Herdr saw it work and then go idle. herdr-say reads this from the transcript of the target pane's Claude session: the message is processed unless the agent's first reply to it is an API rate-limit error. The agent's reply to a message is the first reply after the transcript record that carries that message: Herdr does not track turns, so for an agent already working when the message lands, the state change Herdr sees and the reply after it belong to the running turn. Such a message waits behind the running turn until that turn takes it in or ends, and herdr-say waits for the message's own reply however long that turn runs. A message still not taken in once that turn has ended or the agent's Claude has exited never reached the agent: herdr-say exits failed, and its error output names the target and that the message was never taken in. When that reply is a rate-limit error, herdr-say sends the same message again, each wait longer than the last because the error names no time it clears, until a send is processed and it exits 0. Every send reaches its target as the first one does, so a target parked during a wait is resumed as a parked target is, and the message goes to the resumed agent. When its bound passes and every send's turn died on a rate limit, it exits 69, not processed, and its error output names the target, the number of sends, and the last API error. Exit 69 already holds every re-send, so its sender never sends that message again. The retry lives in that one send, so no inbox, timer, or service holds the message, and its re-sends can take up to about two hours, besides any running turn a message waits behind; a caller bounded tighter does not hold it in the foreground. A Codex or pi agent keeps no Claude transcript, so the state change alone confirms a message to it.

A pane's Claude session is found by one lookup that herdr-say, herdr-close --park, and a native report share: Claude's own per-process session records whose live process carries that pane's HERDR_PANE_ID, and the caller's HERDR_SESSION, in its environment. A process counts whether or not Herdr reports it as the pane's foreground, since a spare Claude process claimed into the pane is that pane's live agent. A record counts only when the process start time it records matches the live process at its pid, so a record an ended Claude left at a pid since reused is never read. Of the records that count, the pane's session is the one whose transcript holds the pane's latest reply.

herdr-wake send runs herdr-say in a session of its own and returns its exit when it ends within Spec Chat's send bound: 0 sent, 75 deferred, and any other failed, with its one-line reason. A send that outlives that bound, resuming a parked owner or waiting out a rate limit, keeps delivering after Spec Chat counts it sent, so a spec review hand-off whose first wake dies on a rate limit still reaches its owner. When such a send then ends deferred or failed, Spec Chat no longer waits on it, so herdr-wake sends its one-line reason, naming the owner, once to the operator's pane, read from the operator.toml of the owner's session.

herdr-spawn starts the agent bare, and its brief follows by herdr-say.

A failed spawn closes the tab it created, and a failed octo-lite-start closes the lane space it created, so no orphan is left. herdr-spawn answers the agent's startup trust dialog at the pane, confirming only once the affirmative row is selected and never a refusal; a dialog that does not clear fails the spawn closed.

There is no acknowledgement step, inbox, or drain.

Each lane, one PR, runs in its own Herdr space labelled with the lane name; the fleet operator runs in a space of its own. octo-lite-start creates the lane space and starts the owner in it, leaving no other tab there, and prints its workspace= beside pane=. The owner spawns every worker of its lane into its own space, $HERDR_WORKSPACE_ID. A lane's own space is the one octo-lite-start created for it; a lane started in a space shared with the operator or other lanes has no space of its own.

A lane's space id is the prefix of its owner pane id, w7 in "w7:p1", so no record key holds it. That space is the lane's own when no other lane's owner pane and not the operator's pane, both read from the session's state, carries the same prefix.

Every worker is spawned under the name <role>-<ticket>, lowercase, for example implementer-ann-64, where the role is the role contract it runs and the ticket is the issue key it works; the lane space already names the lane, and Herdr accepts only lowercase names of at most 32 characters. The ticket is the issue key ending the name, read back in upper case; a worker serving the whole lane, such as the integrator or a reviewer of the integration head, carries the lane's primary issue key. An agent in the lane's space whose name does not follow this form is still a worker of the lane, with no role or ticket. The owner closes a worker once its result is consumed, before spawning the next one under the same name, so a name is live at most once; Herdr refuses a spawn under a live name.

A Claude agent starts under its Herdr name, so Claude's own list of the sessions on the box names a lane's owner by the lane's name and a worker by its spawn name, a resumed agent included.

A Claude agent sends a report, a status, result, or blocker, to a Claude agent by Claude's own messaging, addressed to the target pane's Claude session, so the receiver's conversation records it as a peer's message from the sender's name, never as the operator's input, and it never reaches an agent of another Herdr session. That is the reason for a second way to send: a message herdr-say types is recorded as if the operator typed it. The sender sends by herdr-say instead when the target pane has no live Claude session to address, as for a parked, closed, Codex, or pi agent, or when Claude reports the native send failed or held. A native send counts as sent once Claude reports it delivered to the receiver's queue: a receiver that exits before taking it in loses it, its sender not told, and a turn that takes it in and dies at once on an API rate limit spends it, never sending it again as herdr-say does. A worker's result lost either way is still read from its pane once the owner's wait on it ends (result on screen), and an owner left idle at unfinished work is woken by the fleet operator as one whose turn died mid-task is. Work one agent sets another to, a brief, a resume, a repair, or a human's answer the operator relays, still goes by herdr-say or herdr-await: a wait starts from a send Herdr saw taken in, and a relayed answer must read as the human's. A shell sender, herdr-wake and the sends herdr-await makes included, and a Codex or pi agent send only by herdr-say, since only a Claude turn sends natively; every Claude role contract allows that send.

A lane pane never moves to another space: Herdr rewrites a moved pane's pane and tab ids, which breaks the lane record, review rows, and teardown.

herdr-await is the one wait on a lane agent; roles never run Herdr's own agent wait themselves. Given a message, it first sends that message to the agent with herdr-say, and a send that does not exit 0 ends the wait at once. Otherwise the wait ends when the agent is idle, done, or stuck on an interactive prompt, or is gone because its agent exited or its tab closed. The wait's end names the agent and the stop it ended on: the state the agent stopped in, gone, or the send's failure. A Claude caller asks for a notice and runs the wait as a background task of its own, so the wait's end reaches it as that task's end, never as typed text its conversation would record as the operator's input. For any other caller, a Codex or pi caller or one that does not ask, herdr-await returns at once, waits apart from its caller, and sends the caller's pane one message naming that end. Either way a send that waits out a rate limit holds no caller in the foreground. Given the stop its caller last read, as that message named it, the wait ends only once the agent has changed state since that stop and has stopped again, or is gone, so an agent that works and stops before the wait starts still ends it. Each Herdr wait it runs is bounded, and at the bound it waits again, so the wait ends within that bound once the agent is gone by any means, its tab closed outside herdr-close included, or once an agent has worked and stopped between two of its Herdr waits. It runs as a process of its caller's tab, so closing or parking the caller ends it with the caller's other processes, and a wait whose caller is gone by any other means ends at its bound, waking no one.

Herdr leaves its own wait on an agent running when the agent's tab closes, so a wait on that agent ends as gone at its bound and wakes its caller, whoever else closed the tab. herdr-close, parking included, ends its own caller's waits on every agent in the tab or space it closes, sending no message, and a Claude caller's notice of such a wait names it ended by its caller's close, never a stop, so an owner that closed a worker itself no longer waits on it and never reads that close as news of a worker spawned again under the same name.

herdr-close reports each close as one closed line, on stdout for a close and on stderr for a park, whose stdout is its parked line. An owner that closes a consumed worker appends that closed line to the lane's hand-off log, so every line herdr-close prints for a close or a park, on either stream, is one a hand-off log can hold.

At teardown the operator closes a lane's own space with herdr-close <space id>, which closes the space and stops every process started in it, including detached ones. A lane started in a shared space ends at its owner tab: the operator closes it with herdr-close <owner tab>, and the owner's close report names that tab, never the space.

An idle Claude lane agent is parked with herdr-close --park <pane>: it reads the agent's session id and role from the record of the pane's Claude session, taking the role a worker's spawn name carries when that record names none, closes the agent's tab, or its whole space when that tab is the space's only one, so no live tab beside it closes, and prints one parked line. The parker appends that line to the lane's hand-off log: the operator when it parks an owner, the owner when it parks a worker. A working agent or a Codex or pi agent is refused with nothing closed; only Claude keeps a per-process session file, so parking is Claude only.

A parked agent resumes as it was launched, plus --resume <session>: an owner through octo-lite-start --resume <session> in a new lane space under the lane's name at its worktree, a worker through herdr-spawn --resume <session> in the caller's space under its old name and role, the parked line's role or, when the line names none, the role its spawn name carries; Claude starts with --agent <role> --resume <session> and keeps its conversation.

When Herdr finds no agent for a herdr-say target, the latest parked line naming that pane or name decides: if an agent already runs under the line's name, the message goes to it; otherwise the agent is resumed first, then the message is delivered, and herdr-say prints the resumed agent's pane=. herdr-wake check counts a parked owner as present, so a spec review hand-off to it resumes it.

Risk: whether Herdr keeps space and pane ids across a Herdr server restart is unproven; if it does not, a restart breaks every lane record owner pane and every space derived from it.
