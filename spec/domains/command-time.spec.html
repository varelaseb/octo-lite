Command time

Specifications / Command time

This spec states what every agent octo-lite installs, Claude Code or Codex, is told after each shell command it runs: how long the command took, and a warning when it is repeating a slow command after an edit.

How the installer registers the hook with each agent CLI is in the octo-lite install spec; the same hook checks the box's disk after each command and warns the operator, as the Disk spec states.

User stories

As an agent octo-lite installs, Claude Code or Codex, after each shell command I run I am told how long it took, with any wait for the box lock told apart from the command's own run, so I can weigh what running it again costs.

As an agent that runs the same slow command again after an edit, such as a full test suite after a one-line change, I am warned that I am in a slow iteration loop and told what to run instead.

As an operator, the command-time hook only informs my agents: it never blocks, denies, or changes a command, and when it fails, every command and its result are as they would be without it.

Acceptance criteria

Given a Claude Code agent on a box where octo-lite is installed, When the agent runs a shell command, Then the agent is told, beside the command's result, how long the command took: no screen shows it.

Given a Codex agent on a box where octo-lite is installed and the operator has trusted octo-lite's hook in Codex, When the agent runs a shell command, Then the agent is told, beside the command's result, how long the command took: no screen shows it.

Given an agent on a box where another job holds the box lock for a while, a fixture that must be added to provide it, When the agent runs a command that takes the box lock and reports its wait, Then the agent is told how long it waited for the box lock and how long the command ran, each apart: no screen shows it.

Given an agent on a box where octo-lite is installed, When the agent runs a command that names the box lock without taking it, such as a search for it, Then the agent is told how long the command took, and nothing of the box lock: no screen shows it.

Given an agent in a repository with a file quoting the box lock's wait line inside a longer line, a fixture that must be added to provide it, When the agent runs a search that prints that longer line, Then the agent is told how long the command took, with no wait for the box lock told apart: no screen shows it.

Given an agent that has run a slow command once in its session, a fixture that must be added to provide it, When the agent edits a file in the command's repository, then runs the same command again, Then the agent is told it is in a slow iteration loop, how many times it has run the command and their time in all, and to run only the tests for what it touched, and the full suite once, on the final head: no screen shows it.

Given an agent that has run a slow command once in its session, a fixture that must be added to provide it, When the agent runs the same command again without editing a file, Then the agent is told how long the command took, with no slow-loop warning: no screen shows it.

Given an agent that has run a command that is not slow once in its session, When the agent edits a file in the command's repository, then runs the same command again, Then the agent is told how long the command took, with no slow-loop warning: no screen shows it.

Given an agent that has run, once in its session, a command that waited long for the box lock, reported its wait, and ran briefly, a fixture that must be added to provide it, When the agent edits a file in the command's repository, then runs the same command again with the same wait, Then the agent is told its wait and its run apart, with no slow-loop warning: no screen shows it.

Given an agent that has been warned of a slow iteration loop, When the agent runs the same command again, Then the command runs and its result reaches the agent, with the warning beside it: no screen shows it.

Given an agent on a box where octo-lite's command-time hook fails, needs an induced failure: the hook cannot keep its records, When the agent runs a shell command, Then the command runs and its result reaches the agent as it would without the hook: no screen shows it.

Given an octo-lite contributor's change to any feature that adds or changes a hook octo-lite registers with an agent CLI, When an agent runs a command that hook sees, Then the command runs and its result reaches the agent as it would without the hook, with at most the hook's added context beside it: no hook octo-lite registers blocks, denies, or changes a command, or stops an agent (why): no screen shows it.

Modular boundaries

The command-time hook owns timing each shell command an agent runs, telling a wait for the box lock apart from the run, and judging a slow iteration loop; it also carries the disk warning. The caller-facing seam is each agent CLI's tool hook: the CLI passes the hook each shell command it ran, and the hook returns the line the agent reads. Direction is external-provider: the hook depends on Claude Code's and Codex's hook contracts; neither CLI, nor any octo-lite role or skill, depends on the hook. Observable scope: the line added to an agent's context after each shell command.

Command time

After each shell command an agent runs, octo-lite's command-time hook adds one line to the agent's context, beside the command's result, telling how long the command took. A command still running when its tool call returns, such as one the agent starts in the background or one moved to the background as it runs, has not finished, so it gets no line.

The box lock admits a box's heavy jobs into slots counted from the box. A command that takes the box lock may wait for another job before it runs, and that wait is not the command's own run. A command reports its wait by printing it on a line of its own, as octo-lite-lock and flock --verbose do. That line inside a longer line, such as a search result quoting it, reports no wait, and a command naming the box lock does not take it.

Slow iteration loop

A command is slow when its own run takes at least a minute; a reported wait for the box lock is not counted, and a run whose wait was not reported counts in full.

An agent is in a slow iteration loop when, in one session, it runs a slow command again after a file in the command's repository changed since that command's last run. The same command is the same command text, ignoring the white space around it. A slow command run again with no file changed, such as one that waits on something else, is not a loop, and neither is a command outside a repository.

The line for each run in a slow iteration loop adds a warning: how many times the agent has run the command in this session and their time in all, then what to run instead, only the tests for what it touched, and the full suite once, on the final head.

Inform only

The hook only informs, as every hook octo-lite registers does (rule): it never blocks, denies, or changes a command, and never stops an agent. It is not a guardrail: the warning is the agent's recipe at the point of action, and the agent decides what to run. When the hook fails, it adds nothing, and the command and its result are as they would be without it.
